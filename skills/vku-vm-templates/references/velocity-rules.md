# Правила работы с Velocity

## Источник синтаксиса

Сначала извлечь соглашения из VM той же платформы. Зафиксировать:

- корневые переменные контекста;
- синтаксис доступа к объектам и массивам;
- способы `#if`, `#foreach`, `#set`;
- helpers для XML escaping, дат, справочников и файлов;
- трактовку отсутствующих и пустых значений;
- формат PDF-VM.

Не вводить новый helper или метод только потому, что он существует в стандартном Apache Velocity: окружение платформы может отличаться.

## Безопасная генерация

- Не вставлять значение в XML без подтверждённого escaping.
- Не смешивать проверку наличия со сравнением бизнес-значения.
- Не подавлять `0` и `false` проверкой, предназначенной для пустой строки.
- Не обращаться к элементу массива без проверки существования.
- Различать файловые компоненты по фактическому DTO: `FileUploadComponent` разворачивается в объект с массивом `uploads`, а подтверждённый `PhotoUploadComponent` — в одиночный объект файла с полями `fileName`, `mnemonic`, `fileExt` и `mimeType`; для фотографии не выполнять цикл по `uploads`.
- Не изменять входные данные через `#set`, если это не требуется подтверждённым паттерном.
- Не считать `#set` ошибочным только потому, что валидатор подсветил эту строку: проверить предшествующие незакрытые директивы, допустимость правой части и область видимости переменной. Если точная диагностика недоступна, убрать промежуточный псевдоним и вывести взаимоисключающие ветки напрямую.
- При создании псевдонима вложенного объекта сначала найти подтверждённый в эталонах синтаксис данного платформенного диалекта. Не заменять индексный доступ точечным механически: оба варианта могут различаться для Map/JSON-объектов.
- Не ловить несовместимость XSD условным пропуском обязательных элементов.

## Заимствование примеров

Заимствовать инфраструктурные паттерны: namespace, escaping, даты, циклы, файлы, формат PDF. Не копировать идентификаторы экранов, компонентов, JSON-пути, XPath, тексты заявления и условия другой услуги без отдельного подтверждения.

## Ограничение макросов в ВКУ

По подтверждённому владельцем ограничению ВКУ не использовать #macro и вызовы пользовательских макросов ни в XML-VM, ни в PDF-VM. Писать условия и циклы непосредственно в корневом XML-элементе или массиве описания PDF, с прямыми обращениями к компонентам. Не добавлять вычислительный блок до корня. Возможность #set внутри корневой структуры проверять отдельно по действующему эталону; при отсутствии подтверждения разворачивать ветки без промежуточных переменных. Успех в стандартном Apache Velocity не доказывает совместимость со штатным обработчиком ВКУ.

Имена локальных переменных также проверять на конфликт с объявлениями form-backend: валидатор учитывает объявления, достигнутые через вложенные блоки, а не только переменные компонентов формы.

## Строки, даты и активные источники

Не добавлять цепочки toString/replace/replaceAll как универсальное экранирование: сначала подтвердить обработку текущим штатным контуром и эталонами. Прямой вывод допустим только при проверенной корректности; спецсимволы проверять реальным XML/PDF. Для необязательных строк учитывать trim, не подавляя 0/false. Обязательные поля не скрывать из-за ошибки источника. Форматирование календарной даты проверять на ISO и профильном формате без сдвига дня. Делить длинные тексты по границам Unicode, если XSD ограничивает отдельный элемент; сохранять полное значение.

При выборе альтернативных компонентов использовать управляющий ответ, а не первый непустой источник; пол вычислять по получателю. Подробности: [практические особенности](verified-platform-behavior.md).
