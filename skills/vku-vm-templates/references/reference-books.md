# Справочники и перенос готовых экранов

## Сначала контракт значения

Для Lookup/MapService выписать dictionaryType, выбранный код, отображаемый текст, originalItem/attributeValues и нужные атрибуты. Не считать поле value универсальным: в декодированном выборе могут быть id и text. Имя справочника, коды записей и атрибуты принадлежат текущей услуге; не копировать их из примера.

## Подготовка и публикация

Следующие параметры зафиксированы по рабочему процессу ЕСНСИ; перед применением сверить текущую инструкцию/интерфейс. Простой справочник и агрегатор — разные варианты. В наблюдавшемся процессе имя до 255 символов, код и имена атрибутов до 31: латиница, цифры и _, первый символ — латинская буква. Типы атрибутов: строка, целое, текст, логический. Структура должна иметь системный autoKey и требуемые атрибуты; типовой список использует code/name, составной ключ по code. Не вводить эти имена в уже существующий справочник, если его контракт иной.

Данные проверить на уникальность ключа, пустые обязательные значения и полное соответствие исходному нормативному перечню. Строка/текст в изученном контракте имели предел 5000, целое — ограничение представления; числа уточнять по действующей версии, а не переносить на ограничения полей формы.

Опубликовать изменения и проверить отсутствие нарушений, актуальную версию и статус передачи. Включить использование на портале и повторно открыть карточку, чтобы убедиться, что флаг сохранился. Распространение/индексация могут быть асинхронными. В ВКУ выполнить «Проверить» и дождаться подтверждения нахождения и загрузки данных. Закрытие dropdown/checkbox без повторной сверки не доказывает сохранение.

## Диагностика компонента

Если поиск пуст: проверить публикацию/индексацию, точный код, доступность, атрибут поиска, структуру данных и сетевой ответ. Для карты дополнительно SDK, координаты, адресный атрибут и вычисленный адрес фокусировки. Не заменять справочник произвольным первым найденным только ради зелёного теста. Адрес/режим работы выбранной точки должны попадать в нужный UI и документы по подтверждённым путям.

## Перенос шаблона

Перед заменой старого экрана построить замыкание зависимостей: компоненты, внешние/внутренние экраны, правила, linkedValues/source, JSON Logic, ref кнопок, справочники, logicComponents, циклы и VM. Удалить или переадресовать все старые зависимости согласованно. Новый ID экрана не переименовывает автоматически все внутренние ссылки.

Если зависимость ведёт на отсутствующий ID, сохранить точный пример в частном отчёте и запросить рабочий полный шаблон. Не публиковать ID и бизнес-тексты конкретного примера в общий навык. Наличие такого дефекта не основание обещать автоматическое исправление любого типового компонента.
