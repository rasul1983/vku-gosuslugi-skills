# Работа с формой

## Модель

Зафиксировать первичные источники и версии. Разделить роль подающего и получателя, цели, условия допустимости и способ получения результата. Определить вводимые данные, подтверждения профиля, документы, повторяемые объекты и внешние компоненты. Право на услугу выводить из требований, а не из примера другой формы.

Инвентарь должен включать screens, applicationFields, screenRules, cycledScreenRules, init/initScreens, externalScreenIds, logicComponents. Условие завершения вложенного элемента может задаваться nextDisplay=null. Недостижимость проверять по обоим графам.

Таблица: экран | компонент | источник DTO | смысл | тип | условие активности | кратность | XML XPath | PDF | основание. Назначить новых числовых ID после проверки полноты модели; не считать расположение в JSON реальным порядком.

## Вычисления

Для linkedValue определить argument, source/входы JSON Logic, тип, значение по умолчанию и потребителей. Путь source обычно обращается к развёрнутому ответу компонента, тогда как JSON-путь DTO содержит applicantAnswers и value. Пример:

```text
DTO: scenarioDto.applicantAnswers.component.value.title
source linkedValues: component.title
```

Для показа сложного значения на другом экране создать linkedValues и использовать в HTML аргумент. Прямые ${answer...} внутри HTML не заменяют настройку источника. Каждый путь подтвердить текущим DTO.

У JSON Logic платформы строки могут быть путями к данным; не переписывать их автоматически в стандартный var. Проверить отсутствие ответа, формат даты и код ответа. Идентификатор аргумента и path кнопки должны совпадать посимвольно.

```json
[
  {"argument":"buttonMode","jsonLogic":{"if":[{"==":["answer.component.value","Значение"]},"SIGN","CONTINUE"]}}
]
```

Для кнопки relatedRel должен быть ID ValueCalculator, path — arguments.buttonMode, relation — displayOn, val — SIGN либо CONTINUE. Пример иллюстрирует структуру; реальные условия выводятся из оставшихся видимых шагов.

## Переходы и возвраты

Для каждого допустимого ответа определить единственный следующий экран или логический конец. Отсутствие и пересечение переходов воспроизводить на реальной последовательности. Не смешивать ответы несовместимых веток в искусственном состоянии и не выдавать его за воспроизведённую ошибку.

Смена ответа может очищать последующие данные, но это нужно подтверждать для конкретной ветки и компонента. Наличие поля очистки в экспорте не доказывает наличие настройки в интерфейсе. При формировании XML/PDF использовать активный режим, даже если альтернативное значение осталось в памяти.

Скопированный шаблон проверить на отсутствующие зависимости, встроенные ограничения, ID источников и ожидаемые форматы DTO. Совпадение внешнего вида не гарантирует самостоятельной работоспособности перенесённого экрана.

## Виджеты и тексты

Карты, подтверждения профиля, загрузчики и повторяемые компоненты имеют собственный контракт. Проверять фактические источники адреса, значения справочников, готовность внешних библиотек и автоматически выполняемые переходы.

Формулировки привязывать к получателю услуги, если подаёт представитель. Заголовок, пояснение, label поля и техническое value имеют разные назначения. Короткое объяснение должно помогать заполнить поля; юридические термины менять только без потери смысла. Рекомендации давать в терминах полей конструктора, с точными выражениями и ожидаемым поведением.
